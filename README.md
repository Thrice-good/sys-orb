# 系统占用悬浮球

一个 132px 的圆形桌面浮球，实时显示 CPU 与内存占用。
Rust + egui 原生窗口，不使用任何浏览器内核。

## 形态

```
        ╭───────────╮
     ╭──┤  ◯◯◯◯◯◯  ├──╮      外环 = CPU（青 → 黄 → 红）
    │   │   ◯◯◯◯    │   │     内环 = 内存（紫 → 黄 → 红）
    │   │    27%     │   │     中心 = 主指标
    │   │  MEM 61%   │   │
     ╰──┤           ├──╯
        ╰───────────╯
```

- **无边框、无任务栏图标、背景透明**，圆外像素全部留给桌面
- **总在最前**（可在右键菜单关闭）
- 拖动球体移动，位置自动记住（`%APPDATA%\sys-orb\pos.txt`）
- 双击切换中心显示 CPU 或内存
- 右键菜单：刷新间隔、总在最前、退出

## 颜色阈值

| 占用 | 颜色 | 含义 |
|---|---|---|
| < 60% | 青 / 紫 | 正常 |
| 60% ~ 85% | 黄 | 开始有压力 |
| ≥ 85% | 红 | 满载，卡顿预警 |

## 低功耗设计

悬浮球需要持续刷新，这里做了三件事压低唤醒频率：

1. **采样走 Win32 原生调用**，不用 `sysinfo`。
   `GetSystemTimes` 取两次累计时间的差算 CPU，`GlobalMemoryStatusEx` 直接给内存使用率。
   一次采样两个系统调用，微秒级返回，且不引入任何额外依赖。
2. **一次采样只画一帧**。不是 60fps 动画循环，没有 `requestAnimationFrame` 常驻。
3. **数值稳定时自动降频**。CPU 变化 < 1% 且内存变化 < 0.5% 连续成立时，
   采样间隔按 2 的幂拉长（1.5s → 3s → 6s → 8s 封顶）；一旦有变化立刻回到基础间隔。

所以静止状态下的实际负载是「每 8 秒醒一次、画一帧」。

## 云端构建，本地零安装

仓库推到 GitHub 后，Actions 会自动编译出 exe：

```
Actions → build-windows-exe → 跑完 → Artifacts → sys-orb-windows-x64.zip
```

产物是静态链接的单文件 exe，不需要装 VC++ 运行库。

本地要自己编译的话：

```bash
cargo build --release
# 产物 target/release/sys-orb.exe
```

## 预期数据

| 指标 | 量级 |
|---|---|
| exe 体积 | 5~6 MB |
| 任务管理器「内存」列 | 25~35 MB |
| 空闲 CPU | < 0.5% |
| 冷启动 | < 300 ms |

（同架构的 focus-timer 实测为 24 MB / 5 线程 / 0.00% CPU，本工程只多两个系统调用。）

## 已知限制

**圆角处的鼠标捕获**：窗口在系统里仍是矩形，圆形之外的四个角虽然视觉透明，
但仍会拦截鼠标点击。约占窗口面积的 21%（四个角的弓形区域）。
要彻底解决需要 layered window + 区域裁剪，代码量和风险都不划算，因此保留现状。
